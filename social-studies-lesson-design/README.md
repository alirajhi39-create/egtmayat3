# درس تفاعلي: تأسيس الدولة السعودية الثانية

الدراسات الاجتماعية — الصف السادس الابتدائي — الوحدة الثالثة / الدرس السابع.

## المزايا
- ١٤ شريحة تفاعلية مطابقة للكتاب المدرسي + تقويم من ٨ أسئلة.
- استراتيجيات تعليمية ظاهرة في كل شريحة (العصف الذهني، البطاقات المقلوبة، الخريطة الذهنية، فكر-زاوج-شارك، المطابقة، التدريس التبادلي…).
- مؤثرات صوتية + تعليق صوتي عربي، **قابلة للاستبدال بملفاتك الصوتية**.
- تسجيل دخول الطالب باسمه وفصله.
- خيارات الفصل في شاشة الطالب: **٦/١** و**٦/٢**.
- لوحة معلم: متابعة تقدم كل طالب، إجاباته الكتابية، درجاته، وتصدير Excel/CSV.
- قاعدة بيانات **Neon (Postgres)** عبر دوال **Vercel**، مع وضع محلي احتياطي.

---

## ١) النشر على Vercel

```bash
npm i -g vercel
vercel          # ربط المشروع
vercel --prod   # نشر الإنتاج
```
أو ارفع المشروع إلى GitHub ثم **Import Project** في Vercel (سيكتشف Vite تلقائياً).

### إصلاح خطأ النشر `invalid_function_runtime`
كان `vercel.json` يحدد نسخة runtime للدوال (`@vercel/node@3`) وهذا غير مقبول في Vercel CLI 65.
تم حذف قسم `functions` و`rewrites` بالكامل، وأصبح Vercel يكتشف دوال `api/*.ts` تلقائياً كـ Node Functions.
أعد النشر الآن: **Deployments → ⋯ → Redeploy** (بدون Build Cache).

## ٢) ربط قاعدة بيانات Neon

1. أنشئ مشروعاً مجانياً على <https://neon.tech> واحصل على **Connection String**:
   `postgresql://user:password@ep-xxxx.region.aws.neon.tech/neondb?sslmode=require`
2. في Vercel: **Project → Settings → Environment Variables** أضف:

| المتغير | القيمة |
|---|---|
| `DATABASE_URL` | رابط اتصال Neon |

3. أعد النشر (Redeploy). يُنشئ النظام الجدول تلقائياً عند أول طلب:

```sql
CREATE TABLE lesson_progress (
  id TEXT PRIMARY KEY, student_name TEXT, class_name TEXT,
  lesson_slug TEXT, max_slide INT, total_slides INT,
  quiz_score INT, quiz_total INT, activities JSONB,
  started_at TIMESTAMPTZ, updated_at TIMESTAMPTZ
);
```

> أسرع بديل: من داخل Vercel افتح **Storage → Create Database → Neon**، وسيضيف `DATABASE_URL` تلقائياً.

**بدون قاعدة بيانات** يعمل الدرس كاملاً ويحفظ البيانات والأصوات في متصفح الجهاز فقط، وتظهر في اللوحة علامة «وضع محلي».
لتعمل الأصوات على جميع الأجهزة يجب إضافة `DATABASE_URL`؛ يُنشئ النظام جدول `lesson_sounds` تلقائياً:

```sql
CREATE TABLE lesson_sounds (
  key TEXT PRIMARY KEY,
  mime TEXT NOT NULL DEFAULT 'audio/mpeg',
  file_name TEXT,
  size INT NOT NULL DEFAULT 0,
  data BYTEA NOT NULL,
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

> الحد الأقصى لرفع الملف هو ٤ ميجابايت (قيود Vercel). لملفات أطول، صدّر التسجيل بجودة ٦٤ kbps لتقليل الحجم.

## ٣) لوحة المعلم
- الدخول من زر **👨‍🏫 دخول لوحة المعلم** في شاشة البداية، أو أيقونة 👨‍🏫 في شريط الدرس.
- تتطلب لوحة المعلم إدخال رمز الدخول، دون عرض الرمز أو تلميحات له على شاشة الدخول.
- تُحدَّث البيانات تلقائياً كل ١٥ ثانية.
- بجوار كل طالب زر **تعديل الاسم**. يحفظ Neon الاسم مع بقاء معرف الطالب وفصله ودرجاته وتقدمه وإجاباته وتاريخ بدايته كما هي. لا تعيد طلبات الحفظ القديمة من جهاز الطالب الاسم السابق، وتُحدَّث جلسته عند المزامنة. يتطلب التعديل اتصال Neon حتى لا يكون محلياً مؤقتاً.
- **🗑️ حذف** بجانب كل طالب لحذفه وإجاباته (مع رسالة تأكيد)، و**🖨️ تقرير** لطباعة تقرير الطالب وحده.
- **📄 طباعة بدون الأسئلة**: تقرير مختصر لا يتضمن إجابات أسئلة التقويم (يبقى جدول التقدم والدرجات). يوجد زر مماثل بجانب كل طالب.
- خياران لمحتوى التقرير: **إجابات الأنشطة** و**أسئلة التقويم وإجاباتها** — يمكنك إيقاف أيٍّ منهما.
- **🖨️ طباعة التقرير PDF**: تقرير رسمي لكل الطلاب (أو لفصل محدد عبر مرشح الفصل) فيه ملخص الفصل وجدول التقدم والدرجات وإجابات الأنشطة. في نافذة الطباعة اختر **الوجهة: حفظ كـ PDF**.

### الاحتفاظ ببيانات الطلاب عند إعادة النشر
- بيانات الطلاب في Neon **لا تُمسح عند إعادة نشر Vercel**. يستخدم التطبيق جدول `lesson_progress` الحالي كما هو، دون حذف أو إعادة تهيئة. احرص على بقاء متغير `DATABASE_URL` للإنتاج متصلاً **بنفس قاعدة Neon ونفس الفرع** في النشر الجديد. إذا استخدمت Preview فقد يشير إلى فرع مختلف مؤقت، فلا تعتبره قاعدة الإنتاج الدائمة.
- بعد نجاح قراءة سجلات Neon في لوحة المعلم، يُجرى ترحيل التسميات **6 / أ** و**6 / ب** إلى **٦/١** و**٦/٢** بطلب منفصل. لا يعتمد عرض الطلاب أو حفظ تقدمهم على نجاح هذا الترحيل. يتغير حقل الفصل فقط؛ لا تُحذف السجلات ولا تتغير الدرجات أو الإجابات أو التواريخ.
- إذا لم تظهر سجلات Neon بعد إعادة النشر، افحص أن `DATABASE_URL` لبيئة **Production** ما زال يشير إلى قاعدة البيانات والفرع نفسيهما اللذين يحويان السجلات. قد تشير بيئة Preview إلى فرع آخر. لا يمكن استرجاع تعيين الفصل الفردي الذي عدّله المعلم يدوياً خلال فترة **6 / أ** و**6 / ب** إلا من نسخة احتياطية قديمة أو سجل تاريخي في Neon؛ يعود الاسم الرقمي بناءً على آخر فصل محفوظ لكل طالب.
- لا تستعد فرع Neon بالكامل إلى وقت سابق لمجرد تغيير اسم الفصل؛ الاستعادة الكاملة قد تزيل إجابات أُدخلت بعد ذلك الوقت. استخدم [Time Travel](https://neon.com/docs/postgres/backup-restore/time-travel-assist) لمراجعة السجلات القديمة إن كانت ضمن نافذة تاريخ المشروع، أو استعد السجلات الناقصة فقط من ملف JSON في لوحة المعلم.
- عند عودة الطالب من **نفس الجهاز** بعد تسجيل الخروج، يسأله الموقع إن كان يريد استكمال عمله المحلي السابق إذا تطابق اسمه وفصله، أو تطابق الاسم وحده وكان سجله المحلي فريداً (في حال نقل المعلم الطالب لفصل آخر). اختيار الاستكمال يعيد استخدام معرفه ويحفظ شرائحه وإجاباته ودرجاته وتاريخ بدايته، ثم يزامنها مع Neon. وإذا بدأ من جديد، يظل سجله السابق محفوظاً ولا يُحذف.
- تُحفظ الإجابات الكتابية محلياً فور كتابتها، وتظهر من جديد عند الرجوع إلى النشاط أو استكمال الجلسة؛ تُرسل التغييرات إلى Neon في الخلفية دون مسح الإجابات السابقة.
- إذا انقطع اتصال الطالب أثناء الإرسال، يبقى عمله محفوظاً على جهازه، وتُعاد محاولة إرسال **آخر تقدم غير متزامن** إلى Neon عند عودة الاتصال أو فتح الصفحة أو العودة إليها، دون إرسال طلبات مكررة بعد نجاح المزامنة.
- في لوحة المعلم افتح **النسخ الاحتياطي وحفظ بيانات الطلاب** لتنزيل ملف JSON بكل البيانات، ثم استعد منه السجلات الناقصة إذا نقلت المشروع أو غيرت القاعدة. الاستعادة لا تحذف ولا تستبدل السجلات الموجودة.
- إذا كانت لديك سجلات قديمة محفوظة **على جهاز المعلم فقط**، يظهر زر **نقل السجلات السابقة إلى Neon** بعد ربط القاعدة. البيانات المحلية على أجهزة أخرى لا يمكن نقلها تلقائياً من جهاز المعلم؛ افتح تلك الأجهزة متصلة بالموقع أو أنشئ نسخة احتياطية منها قبل تغيير النطاق.
- ملف النسخة الاحتياطية يحتوي أسماء الطلاب وإجاباتهم ودرجاتهم؛ احتفظ به في مكان خاص ولا تشاركه مع الطلاب.

### إذا ظهر «وضع محلي» بدلاً من Neon
في شاشة Vercel قد يكون `DATABASE_URL` ظاهراً ضمن **Production** ومع ذلك لا يكون النشر الحالي قد التقط قيمته؛ تغييرات المتغيرات لا تعمل حتى إنشاء نشر جديد. وسم **Needs Attention** سبب لمراجعة اتصال مورد Neon، لكنه وحده لا يثبت أن قاعدة البيانات لا تعمل. استخدم قاعدة Neon الموجودة نفسها، ولا تنشئ قاعدة جديدة أو تستبدلها بمتغيرات KV.
1. افتح رابط موقع **Production** متبوعاً بـ `/api/progress`. إذا ظهر JSON برمز `DATABASE_URL_MISSING`، أضف `DATABASE_URL` في **Vercel → Project Settings → Environment Variables** لبيئة Production. وإذا ظهر `PROGRESS_TABLE_MISSING` فالغالب أن الاتصال يشير إلى فرع لا يحتوي جدول الطلاب؛ تحقق من الفرع القديم قبل إنشاء جدول جديد. وإذا ظهر `NEON_REQUEST_FAILED`، راجع سجلات Functions وصحة اتصال Neon. ظهور HTML أو 404 يعني أن دالة `api/progress.ts` لم تُنشر.
2. إذا عاد `ok: true` مع `students: []`، فالاتصال يعمل لكن القاعدة أو الفرع الحالي فارغ. راجع فرع Neon الذي يحوي السجلات القديمة، ولا تنشئ سجلات جديدة قبل التأكد من عنوان اتصال Production.
3. إذا كانت قاعدة Neon موجودة ووسم المتغير **Needs Attention**، افتح **Vercel → Storage → قاعدة Neon الحالية → Connect Project** وتحقق من اتصال المشروع ببيئة Production وفرع الإنتاج الذي يحوي الطلاب. إذا كان الاتصال من Neon، راجع **Neon → Integrations → Vercel → Production branch**. لا تحذف المورد القديم أثناء الفحص.
4. اضغط **Redeploy** الظاهر بعد تعديل المتغيرات؛ النشر القديم لا يلتقط القيم الجديدة تلقائياً. لا تشارك رابط `DATABASE_URL` أو كلمة مرور القاعدة في رسالة عامة.

تغيير أسماء الفصول إجراء منفصل عند دخول لوحة المعلم: إذا فشل لا تُحجب سجلات الطلاب، وستظهر التسميات `٦/١` و`٦/٢` على الموقع مع بقاء بيانات Neon كما هي.

## ٤) استبدال الأصوات بملفاتك
من لوحة المعلم → تبويب **🎙️ إدارة الأصوات**:
- **المؤثرات**: نقرة التنقل، قلب البطاقة، كشف المعلومة، إجابة صحيحة، إجابة خاطئة، نجاح.
- **التعليق الصوتي**: ملف مستقل لكل شريحة من الشرائح الـ١٥ (سجّل شرحك بصوتك).
- **أصوات أسئلة التقويم:** ملف مستقل **لكل سؤال من أسئلة التقويم الثمانية** (`السؤال ١` … `السؤال ٨`).
  - يظهر زر «🔊 استمع للسؤال» مع كل سؤال في التقويم، ويُشغّل ملف السؤال الحالي تلقائياً عند الانتقال بين الأسئلة.
- **تخزين سحابي:** كل ملف يُرفع إلى قاعدة بيانات Neon (`lesson_sounds`) عبر `api/sounds.ts`، لذا يسمعه الطلاب على **جميع الأجهزة**، مع نسخة محلية (IndexedDB) لتشغيل أسرع.
- يبدأ تشغيل الملف السحابي مباشرة دون انتظار تنزيله كاملاً؛ تُهيَّأ أصوات الشريحة الحالية والتالية في الخلفية، وكذلك السؤال الحالي والتالي في التقويم. تدعم واجهة الأصوات طلبات Range لمتصفحات الجوال، وتستخدم روابط بإصدار الملف لتخزين الصوت على CDN دون تشغيل نسخة قديمة بعد الاستبدال.
- عند الانتقال إلى شريحة أو سؤال آخر، أو بدء ملف أو مؤثر جديد، يُوقف المشغّل الصوت السابق وطلبات تشغيله المعلّقة. تُحدَّث قائمة الأصوات عند العودة للصفحة وخلال الدرس دورياً.
- الصيغ المدعومة: MP3 / WAV / M4A / OGG — **الحد الأقصى ٤ ميجابايت للملف**.
- شارة لكل ملف: **☁️ على كل الأجهزة** أو **📱 هذا الجهاز فقط**.
- زر **🔄 مزامنة الملفات المحلية** يرفع الملفات القديمة التي رُفعت قبل تفعيل السحابة.
- الحذف يزيل الملف من السحابة ومن الجهاز معاً.

| التقويم — السؤال ١ | `voice-slide-13-q1` |

### بديل: أصوات ثابتة مع المشروع
ضع الملفات في `public/audio/` ثم اربطها بالمفاتيح: `sfx-click`, `sfx-flip`, `sfx-reveal`, `sfx-correct`, `sfx-wrong`, `sfx-success`, و`voice-slide-0` … `voice-slide-14`.
